## Objective

Phase 8 shipped the rule engine with three named IOUs: the C++/Python indicator
implementations had no drift guard, the portfolio's fully-tested short-selling
path was unreachable from any user-facing surface, and the OHLCV cache died
with the container on every redeploy. Phase 9 closes all three.

## 9.1 Indicator Cross-Validation (ADR-048)

- `backtester/include/strategy/Indicators.hpp` — indicator math extracted from
  `RuleStrategy` into pure free functions so formulas are testable in isolation.
- `tests/fixtures/indicator_crossval.csv` — deterministic 60-bar fixture
  (generated by `scripts/gen_indicator_fixture.py`, seeded RNG, checked in)
  with expected SMA/EMA/RSI/HIGH_N/LOW_N values, including a forced 15-bar
  rally so the RSI loss==0 branch is exercised on both sides.
- Both suites pin against the same file: `test_indicators_crossval.cpp` (C++)
  and `test_indicator_crossval.py` (Python). Drift in either implementation
  fails exactly one suite, pointing at the divergence.
- The pipeline's stream-stateful EMA and the engine's window-seeded EMA differ
  **by design**; a dedicated test asserts the divergence so silent convergence
  (or accidental "fixes") get flagged too.

## 9.2 Rules v2 — Short Direction (ADR-049)

- Spec format gains `version: 2` with an optional `direction: long|short` key.
  `direction` under `version: 1` is a parse error, so a v1-only consumer can
  never mis-run a short spec as long.
- Same single-sided state machine in both modes: entry conditions open the
  position (LONG or SHORT signal), exit conditions close it (EXIT — the
  portfolio already covers shorts on EXIT).
- `main.cpp` enables `allowShort` from the parsed spec — the spec is the
  single source of direction, so strategy and portfolio can't disagree.
- API: `StrategyRules.direction` (`"long"` default). Long payloads and spec
  files stay byte-identical to Phase 8 (stable cache hashes for saved
  strategies); templates remain long-only.
- Extension: a Long/Short select in the custom rules builder; short saved
  strategies round-trip; result line shows "(short)".

## 9.3 Durable OHLCV Cache

- `OHLCV_CACHE_DIR` env override in `research/data/fetcher.py`.
- Fly: cache lives on the existing volume (`/app/models/ohlcv` — Fly allows
  one volume per machine). Compose `hosted` profile: named `ohlcv_cache`
  volume. Fetched tickers now survive redeploys, keeping each ticker a
  one-time network cost.

## Exit Criteria

- [x] Both cross-validation suites pass against one checked-in fixture; a
  deliberate formula change fails the corresponding suite
- [x] A short custom strategy runs end-to-end through the real binary
  (verified: RSI>70 short over full AAPL history → 45 SHORT fills, covers on
  EXIT, `allow_short` enabled from the spec)
- [x] Long strategies emit byte-identical spec files and cache hashes vs
  Phase 8 (regression-tested)
- [x] `direction: short` under `version: 1` fails in the C++ parser and
  `direction: "sideways"` fails at the API boundary
- [x] All suites green: C++ (incl. new parser/strategy/cross-val tests),
  Python (incl. fixture + direction + cache-dir tests), extension Node tests
- [ ] Post-merge: verify the Fly volume cache path on a real deploy (with 7.4)

## Deferred to Rules v3 (not scheduled)

OR-condition groups (DNF), non-price indicators (volume, ATR), per-strategy
position-sizing overrides, stop-loss/take-profit as first-class exits. Each
bumps the spec version; the version-gating pattern established here is the
migration mechanism.
